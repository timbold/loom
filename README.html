🚊 Loom

Create beautiful, geographically accurate or schematic transit maps from GTFS feeds and custom line graphs. Loom orchestrates data preparation, optimization, and rendering so you can focus on designing compelling transit experiences.

Highlights

End-to-end pipeline

Transform raw GTFS feeds into printable or digital transit maps with minimal manual effort.

Flexible layouts

Generate geographically faithful, octilinear, or orthoradial schematics in a single workflow.

Powerful optimization

Choose from ILP, hybrid, stochastic, and greedy solvers tailored to complex transit networks.

Production-ready rendering

Fine-tune labels, padding, and exported layers for publication-quality maps.

Requirements

Core dependencies

  • cmake
  • gcc ≥ 5.0 or clang ≥ 3.9
  • libicu development files (e.g. libicu-dev)

Optional enhancements

  • libglpk-dev, coinor-libcbc-dev, gurobi
  • libzip-dev, libprotobuf-dev
  • freetype2 (libfreetype) for precise label rendering

Installing FreeType

Debian / Ubuntu

sudo apt-get install libfreetype6-dev

macOS (Homebrew)

brew install freetype

Windows (vcpkg)

vcpkg install freetype

Loom ships the TT Norms Pro font under data/fonts and relies on FreeType for accurate label measurement and rendering.

Building Loom

Clone the repository

git clone --recurse-submodules https://github.com/ad-freiburg/loom.git

Update submodules

cd loom
git submodule update --init --recursive

Install ICU development files

sudo apt-get install libicu-dev

Configure & build

cd loom
mkdir build && cd build
cmake ..
make -j

Optional install

make install
You can run the binaries directly from ./build without installing them system-wide.

Toolchain Overview

Tool Purpose
gtfs2graph Convert GTFS feeds into GeoJSON line graphs.
topo Clean graphs, remove overlapping segments, infer turn restrictions.
loom Compute optimal line orderings using ILP, hybrid, or heuristic solvers.
octi Generate schematic layouts on octilinear or orthoradial grids.
transitmap Render the final line graph as SVG or MVT vector tiles.

Quickstart

The examples/ directory contains ready-made overlapping-free line graphs.

cat examples/stuttgart.json | loom | transitmap > stuttgart.svg
cat examples/stuttgart.json | loom | transitmap -l > stuttgart-label.svg
cat examples/stuttgart.json | loom | transitmap -l --single-route-labels=false \
  > stuttgart-label-interchanges.svg
cat examples/stuttgart.json | loom | octi | transitmap -l > stuttgart-octilin.svg
cat examples/stuttgart.json | loom | octi -b orthoradial | transitmap -l > stuttgart-orthorad.svg
cat examples/stuttgart.json | loom | transitmap --padding-top 50 --padding-left 20 > stuttgart-pad.svg

Tips & Tricks

  • Run any tool with -h for a complete list of options.
  • Export individual map layers by toggling switches like --labels, --no-render-stations, and --no-render-node-connections.
  • Hide strokes entirely by setting --line-width 0 --outline-width 0 before exporting a layer.

Key loom Parameters

Preprocessing

Preserve the original topology by disabling untangling and pruning with --no-untangle and --no-prune.

Input format

Parse DOT graphs instead of GeoJSON with -D/--from-dot.

Optimization strategy

Select from ILP (ilp, ilp-naive), hybrid (comb, comb-no-ilp), exhaustive (exhaust), local search (hillc, hillc-random), simulated annealing (anneal, anneal-random), greedy variants, or null. Repeat stochastic solvers with --optim-runs <n>.

Penalty weights

Adjust crossings and separations using --same-seg-cross-pen, --diff-seg-cross-pen, --in-stat-cross-pen-same-seg, --in-stat-cross-pen-diff-seg, --sep-pen, and --in-stat-sep-pen.

ILP configuration

Control solver choice, threads, and time limits via --ilp-solver, --ilp-num-threads, and --ilp-time-limit.

Diagnostics

Inspect solutions with --output-stats, --write-stats, --dbg-output-path, and --output-optgraph.

Start with the default comb-no-ilp strategy. Increase penalties for stubborn crossings or separations, and keep preprocessing enabled unless you need to debug the raw input graph.

Configuration

All tools consult optional .loom.ini files for default settings. Configuration is resolved in the following order:

  1. $HOME/.loom.ini
  2. .loom.ini next to the executable
  3. Command-line flags
  4. --config=<file> overrides the above when supplied explicitly

See loom.ini for supported keys and defaults. Adjust log-level (or use --log-level) from 0 (errors only) to 4 (verbose debug). Default is 2.

Terminus route labels

  • station-label (default) – Anchor to the positioned station name label.
  • stop-footprint – Anchor to the combined polygon footprint.
  • node – Fall back to the raw node position.

Station label candidates

  • station-label-angle-steps – Number of evenly spaced orientations (must be divisible by four).
  • station-label-angle-step-deg – Angular distance in degrees between successive samples.

Text sizing

  • Enable textsize-constant to treat label sizes and spacing as typographic points converted to CSS pixels.
  • Use --textsize-range-pt <min,max> to keep text resolution-dependent but clamp station and terminus label sizes.

Tool Capabilities

  • gtfs2graph – Generate GeoJSON line graphs from GTFS feeds.
  • topo – Remove overlapping edges and infer turn restrictions.
  • loom – Compute optimal line orderings for a line graph.
  • octi – Convert a line graph into schematic layouts on base grids.
  • transitmap – Render a line graph as SVG or MVT vector tiles.

Command-Line Reference

gtfs2graph

  • -m, --mots <modes> – Modes of transport to process (default all).
  • -p, --prune-threshold <0..1> – Threshold for pruning seldomly occurring lines (default 0).
  • -h, --help – Show help message.
  • -v, --version – Print version.

topo

topo consumes the raw line graph created by gtfs2graph (or any equivalent tool) and cleans it up before layout. The most commonly tuned parameters are:

  • -d, --max-aggr-dist <meters> – Maximum distance for merging parallel or overlapping segments (default 50).
  • --sample-dist <length> – Sampling step when constructing support points (default 5 pseudometers).
  • --smooth <factor> – Optional smoothing factor applied after aggregation.
  • --max-comp-dist <meters> – Maximum gap when grouping nodes into distance-based components (default 10000).
  • --write-components, --write-components-path <dir> – Annotate edges with component IDs and export components as GeoJSON.
  • --infer-restr-max-dist <meters> – Search radius for candidate turns (defaults to --max-aggr-dist).
  • --max-length-dev <meters> – Maximum detour allowed when validating inferred restrictions.
  • --turn-restr-full-turn-angle <angle> / --turn-restr-full-turn-pen <penalty> – Penalize sharp “full turns.”
  • --no-infer-restrs – Skip restriction inference entirely.
  • --random-colors – Populate missing line colors before processing.
  • --write-stats, --aggr-stats – Emit run statistics.
  • -h, --help; -v, --version – Standard CLI helpers.

loom

  • --no-untangle – Do not apply untangling rules.
  • --no-prune – Do not apply pruning rules.
  • -m, --optim-method <method> – Select optimization method (default comb-no-ilp).
  • --same-seg-cross-pen <weight> – Penalty for same-segment crossings (default 4).
  • --diff-seg-cross-pen <weight> – Penalty for different-segment crossings (default 1).
  • --in-stat-cross-pen-same-seg <weight> – Penalty for same-segment crossings at stations (default 12).
  • --in-stat-cross-pen-diff-seg <weight> – Penalty for different-segment crossings at stations (default 3).
  • --sep-pen <weight> – Penalty for separations (default 3).
  • --in-stat-sep-pen <weight> – Penalty for separations at stations (default 9).
  • --ilp-solver <solver> – Preferred ILP solver (glpk, cbc, or gurobi; default gurobi).
  • --ilp-num-threads <n> – Number of threads for the ILP solver (0 for solver default).
  • --ilp-time-limit <sec> – ILP solve time limit (-1 for infinite runtime).
  • --output-stats, --write-stats – Print or write statistics.
  • --dbg-output-path <path> – Directory for debug output.
  • --output-optgraph – Write the optimization graph to the debug path.
  • -h, --help; -v, --version – Standard CLI helpers.

octi

octi turns the topological line graph produced by loom into a schematic map that follows a configurable base grid.

Optimization & input control

  • -m, --optim-mode <heur|ilp> – Choose between the fast heuristic placer (default) and the exact ILP optimizer.
  • --obstacles <file> – Provide GeoJSON polygons that the layout must avoid when routing edges.
  • --edge-order <method> – Control how edges are ordered before the search (num-lines, length, adj-nd-deg, etc.).
  • --loc-search-max-iters <n> – Limit refinement iterations in the local improvement stage (default 100).
  • --geo-pen <weight> – Penalize deviation from the original geometry (default 0).

Grid construction & base graph

  • -g, --grid-size <len or %> – Set the grid resolution as an absolute length or percentage of average station spacing (default 100%).
  • -b, --base-graph <type> – Choose the base grid (ortholinear, octilinear, orthoradial, quadtree, or octihanan; default octilinear).
  • --hanan-iters <n> – Refinement iterations when using the octihanan grid.
  • --max-grid-dist <n> – Cap how many grid steps candidates may move from their original position (default 3).

Error handling

  • --retry-on-error – Retry the placement up to 30 times with a reduced grid size when the solver fails.
  • --skip-on-error – Skip the current graph instead of aborting the pipeline on failure.

ILP solver configuration

  • --ilp-solver <solver>, --ilp-num-threads <n>, --ilp-time-limit <sec> – Control backend, threading, and runtime.
  • --ilp-cache-dir <dir>, --ilp-cache-threshold <val> – Cache ILP subproblem solutions.

Penalties & layout preferences

  • --density-pen <weight> – Penalize crowded station clusters (default 10).
  • --vert-pen, --hori-pen, --diag-pen – Weigh the use of vertical, horizontal, and diagonal grid directions.
  • --pen-180, --pen-135, --pen-90, --pen-45 – Add bend penalties for corresponding angle changes.
  • --nd-move-pen <weight> – Penalize moving nodes away from their input location.
  • -h, --help; -v, --version – Standard CLI helpers.

transitmap

  • --line-width <px>, --line-spacing <px>, --outline-width <px> – Control stroke styling.
  • --log-level <0..4> – Logging verbosity (default 2).
  • --render-dir-markers, --dir-marker-spacing <n>, --tail-ignore-sharp-angle, --bi-dir-marker, --crowded-line-thresh <n>, --sharp-turn-angle <rad> – Configure direction marker rendering.
  • -l, --labels; -r, --route-labels – Enable station and route labels.
  • --line-label-textsize, --line-label-bend-angle, --line-label-length-ratio – Tune line label placement.
  • --station-label-textsize, --textsize-constant, --textsize-range-pt, --me-label-textsize, --font-svg-max – Control typography.
  • --station-line-overlap-penalty, --station-line-overlap-per-line, --station-label-far-crowd-radius, --station-label-far-crowd-penalty, --side-penalty-weight, --same-side-penalty, --reposition-label, --cluster-pen-scale, --outside-penalty, --orientation-penalties, --terminus-angle-penalty – Manage label crowding and placement penalties.
  • --route-label-gap, --route-label-terminus-gap, --terminus-label-anchor, --compact-terminal-label, --compact-route-label, --highlight-terminal, --terminus-highlight-fill, --terminus-highlight-stroke – Configure terminus labels and highlighting.
  • --no-deg2-labels, -D/--from-dot, --resolution, padding flags, --smoothing, --ratio, --tl-ratio, --random-colors, --tight-stations, --no-render-stations, --no-render-node-connections, --render-node-fronts – Control overall map layout.
  • --bg-map, --bg-map-webmerc, --bg-map-opacity, --extend-with-bgmap, --geo-lock, --geo-lock-bbox – Overlay background geometry and manage geographic bounds.
  • --landmark, --landmarks, --force-landmarks, --landmark-search-radius, --displacement-iterations, --displacement-cooling, --landmarks-webmerc – Add and control point-of-interest landmarks.
  • --me, --me-size, --me-label, --me-star, --me-station, --me-with-bg, --me-bg-fill, --me-bg-stroke, --me-label-color, --me-station-fill, --me-station-border – Highlight user location.
  • --print-stats; -h, --help; -v, --version – Diagnostics and CLI helpers.

Line Graph Extraction from GTFS

Use gtfs2graph to extract line graphs from GTFS feeds:

gtfs2graph -m tram freiburg.zip > freiburg.json

Clean overlapping geometry with topo:

gtfs2graph -m tram freiburg.zip | topo > freiburg.json

Then run the full octilinear pipeline:

gtfs2graph -m tram freiburg.zip | topo | loom | octi | transitmap -l > freiburg.svg

Adjust optimizer, base graph, and renderer flags to tailor the result to your network.

Landmarks & Location Markers

transitmap can annotate maps with landmarks defined inline or loaded from files. Relative icon paths resolve against the landmark file location.

  • --landmark – Add a single landmark inline (word:text,lat,lon[,fontSize[,color[,opacity]]] or iconPath,lat,lon[,size]).
  • --landmarks – Load multiple landmarks from a text file.
  • --force-landmarks, --landmark-search-radius, --displacement-iterations, --displacement-cooling – Control landmark placement and overlap handling.
  • --landmarks-webmerc – Treat coordinates as Web Mercator rather than WGS84.
  • --me, --me-station, --me-with-bg, --me-star, and related options – Highlight "YOU ARE HERE" locations.
cat examples/stuttgart.json | loom | transitmap --landmarks examples/landmarks.txt > stuttgart-landmarks.svg
cat examples/stuttgart.json | loom | transitmap --landmark word:CityHall,47.9210,106.9175,150,#ff0000 > stuttgart-cityhall.svg

The sample landmarks reference locations around Ulaanbaatar; human-readable names live in examples/ulaanbaatar_landmark_names.txt.

Docker Usage

Build a containerized toolchain using the provided Dockerfile:

docker build -t loom .

Run any tool from the suite inside the container:

docker run -i loom <TOOL>

Example (octilinearize the Freiburg demo):

cat examples/freiburg.json | sudo docker run -i loom octi
To use Gurobi inside the container, mount a directory containing a valid gurobi.lic to /gurobi/: 
docker run -v /home/user/gurobi:/gurobi loom <TOOL>

Replace <TOOL> with the desired binary (loom, octi, etc.) and pass any additional flags.
